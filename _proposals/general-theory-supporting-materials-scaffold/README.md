# General Theory Supporting Materials Scaffold

Status: draft proposal pack, not canon promotion.

Purpose:

Create a detailed set of physical, spiritual, and bridge atoms for the General Theory support layer behind the Master Equation. These atoms are intended for review, reconciliation, later ledger import, and future mind-map rendering.

Source basis:

- Local Theory/General notes previously captured from the Faith Through Physics archive.
- Existing Master Equation atoms in `master-equation/01_canonical`.
- Mapping discipline in `_docs/PHYSICAL_SPIRITUAL_ATOM_MAPPING_PLAN.md`.
- Claim-layer discipline in `_docs/CLAIM_LAYER_TRUTH_CAPSULE_SPEC.md`.

Rule:

Each support concept is split into:

1. a physical atom,
2. a spiritual atom,
3. a bridge atom.

The bridge is where the claim lives. The physical definition and spiritual definition stay useful even if the bridge is demoted.

Current files:

- `general_theory_atoms.v0.1.json` - draft atom set for state, table, conservation, flux, energy flux, equilibrium, superposition, random motion, noise, and speed limit.
- `EQUATION_COMPLETENESS_AND_UNIVERSAL_ATOM_LAYER.md` - expansion plan for all-physics/all-spiritual atom layers and the equation/process completeness standard.
- `PHYSICS_ONTOLOGY_TREE.md` - layered physics family/subfamily classification tree for future atoms and mind-map zoom levels.
- `ATOM_RAIL_IMPORT_NOTES.md` - notes on the existing Python/Postgres atom rail and how it should adapt into this proposal flow.
- `MASTER_SCHEMA_ALIGNMENT.md` - alignment notes for the master invariant, physics atom schema, worldview schema, and physics-numbers bridge rules.
- `PHYSICS_CLAIM_SCHEMA_CONFORMANCE.md` - explicit check showing that the current draft follows the schema discipline but is not yet a full `physics_claim` schema instance.

Import guard:

Do not import these directly into the Lane 4 ledger until they pass:

1. duplicate/reconciliation check against existing atoms,
2. source artifact check,
3. bridge grade review,
4. negative guard review,
5. JSON schema or importer adaptation,
6. dry-run mind-map rendering.
