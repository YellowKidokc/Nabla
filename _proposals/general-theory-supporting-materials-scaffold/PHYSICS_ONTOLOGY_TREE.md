# Physics Ontology Tree

Status: draft proposal, not canon promotion.

Purpose:

Define the layered physics classification needed before the project can honestly say it has mapped physics rather than a small hand-picked subset of physics.

Classification does not prove the claims.

Classification makes the claims inspectable.

## Why Build This

The more carefully the framework classifies physics, the less room there is for vague dismissal.

A critic should not be able to say, "You are just using physics words loosely."

The answer should be:

Show the atom.
Show the domain.
Show the equation.
Show the boundary.
Show the bridge grade.
Show the kill condition.

That is the point of the ontology.

## Tree Shape

Use this depth model:

```text
Physics
  -> Family
    -> Subfamily
      -> Concept Atom
        -> Equation Atom
          -> Variable Atom
          -> Operator Atom
          -> Boundary-Condition Atom
          -> Regime / Approximation Atom
          -> Manifestation Atom
          -> Measurement Atom
          -> Failure-Mode Atom
          -> Spiritual Bridge Atom
```

Each layer should be separately inspectable.

The bridge should never be hidden inside the physics definition.

## Classification Burden

Each physics atom should eventually answer:

1. Which family does it belong to?
2. Which subfamily does it belong to?
3. Is it a concept, equation, variable, process, manifestation, measurement, or guard?
4. What standard physics definition anchors it?
5. What equations or laws depend on it?
6. What equations or laws does it depend on?
7. Where does it manifest physically?
8. What boundary conditions apply?
9. What regime or approximation applies?
10. What would misuse the term?
11. Which spiritual atoms are candidate bridges?
12. Which Master Equation roles does it support?

## Anti-Inflation Rule

Classification increases clarity, not truth value.

A weak bridge with perfect classification is still a weak bridge.

The win is that now we know exactly where it is weak.
